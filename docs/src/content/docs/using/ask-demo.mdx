import { ASK_DEMO } from '../../../data/live.mjs';

The ask demo is a page at <a href={ASK_DEMO}>behold-ask-demo.intentius.workers.dev</a>. A person asks their coding agent to load their estate into behold, then asks one question about it in plain words. The agent asks behold with a Cypher query over the estate's graph, and the page shows the whole exchange: the prompt and the agent's reply in the prompt pane at the bottom, the query and the rows it returned in the graph pane on the right, and the answer's resources lit on the estate graph. A question shows in order: while behold runs it, its query fills the Cypher box and LadybugDB's logo beside it turns for a couple of seconds; as the agent's reply starts, the answer draws and the estate graph frames what it names; the rows show a moment later, while the reply is still typing. Each part is outlined for a moment as it changes, and with reduced motion they show together. A moment after the agent's reply has printed, the prompt pane closes so the estate graph and the graph pane have the room; **Show the conversation** at the bottom edge opens it again and keeps the page on that question until you move on. The first loop plays the agent loading the estate in full. Each later loop asks the next question, with the prompt pane open again: the load shows already done, and the question starts typing within a few seconds. **Next question** moves on the same way. A loop lasts as long as its question takes to answer, then gives you about 15 seconds with the Cypher box (below), and the header counts the question once it is on screen. In a hidden tab the page stops where it is and goes on when you come back.

## Reading an answer

The estate graph frames every card the answer lit and dims the rest. For "If GCP has an outage, which of our domains go with it?" that is the Route 53 records at the top of the estate and the GCP resources they reach at the bottom, so both ends stay in view even though the view then zooms in only a little.

In the graph pane the rows come first, then a drawing of them. When a row pairs two resources, such as a record and what it `reaches`, the drawing puts the first column's resources on the left and the others on the right, joined by edges, with the column's name once above the resources it reaches. A dashed edge is one the answer itself carries that behold derived: one resource's attribute holds the other's cloud id. The edge is labelled with that attribute when it is the only one, and a line under the drawing names the attribute and says what the dashes mean. Those edges are the answer's rows as the query paired them; behold adds no join of its own. A column counts as resources only when every value in it is the key of a resource the recording loaded. A query you run yourself is drawn the same way.

A line above the rows says what the answer found, such as "2 domains depend on 4 resources in the gcp member". It is filled from the recorded rows, like the reply. For a query you run yourself it counts the rows and the resources instead.

Click a row or a node in the drawing, or move to one with Tab and press Enter, to show it on the estate graph. A row lights both of its resources; a node lights itself and every resource a row pairs it with. The view frames them, and a card gives the resource's kind, name and source, where the workspace declares it (with its file when the estate graph knows one), and its cloud id. A resource that only an index read, with no declared resource sharing a cloud id, shows the ownership marker the index found on it, or says the workspace declares nothing for it. Escape clears the selection and goes back to the answer's view. The card uses only what the page already loaded.

Above the query, a line says what the agent asked behold through its `ask` tool; the call as the agent made it shows when you hover over that line. The replies and the list of sources name each source in words, such as the aws member, the azure member's choudoufu graph or the AWS account's index. Its scope key (`chant/aws`, `cloud/aws/<account>/<hash>`) stays in the rows table and shows on hover. During the load turn the pane lists what behold loaded, one source per row, and shows no query; its busy line says in words what behold is reading, and the commands that did it show when you hover over the line above the table. In the rows, a column of resource keys shows a short name: a workspace resource's id (`webRule` for `gcp/webRule`), or an indexed resource's name; the whole key shows on hover and in the card you get by selecting the row. On a phone, once the reply has printed, the answer moves up under the estate graph, ahead of the conversation and the query, and the drawing keeps its size and scrolls sideways in its own box.

## What is recorded

The answers on the page are a recording. They come from one run of behold on emulators. The page's header says so, with the date of that run, and links to behold's docs, this page and [running the same loop on your estate](#the-same-loop-on-your-estate). **About this recording**, under the graph pane, gives the versions of behold, chant, choudoufu and plunge the run used, and the command that records it again. The estate was:

- `example-three-cloud`, a chant workspace with members on chant, choudoufu and plunge, applied to the floci, floci-az and floci-gcp emulators (see [the three-cloud demo](/behold/using/three-cloud/));
- the emulated AWS account, indexed with `behold index aws`, holding a bucket and a role that nothing in the workspace declares;
- a kind cluster indexed with `behold index kubernetes`, whose ServiceAccounts name roles in that account;
- for "Is SSH open to the internet anywhere in our AWS account?", one read of a real AWS account's `us-west-2` region, with its security groups and their ingress rules, kept as an index version with the account id replaced by `123456789012`. floci lists no security group ingress rules, so this read is the only part of the recording that did not run on an emulator.

Each question is one call to the `ask` tool of `behold mcp`, made against `behold serve` of that estate, and the page plays the rows behold answered. The prompts are worded as an engineer would ask them. Before it calls behold, the agent says in one line how it reads the question, for example "I'll find the DNS records that depend on GCP resources." That line sits between the prompt and the busy line. The prompts, those lines and the agent's replies were written for the demo. Every number and every resource in a reply is from the recorded answer. While the page plays, nothing reads a cloud, a cluster or a behold server.

## Your own query

While the recording plays, the Cypher box is marked **Playback** and shows the query behold ran for the agent. Once the agent's reply has printed it is marked **Your turn**, Ask lights up, and a line counts down to the next question. Press **Stay on this question**, or do anything on the page (click, type, scroll the pane, zoom the estate), and the countdown stops until you press **Next question**. The page never clears a query you wrote: when you move on, your next turn offers it back with **Use your last query**.

On your turn, edit the query, or write a new one, and press Ask. It runs in your browser, in LadybugDB's WebAssembly build, over the rows the recording loaded. The rules are the ones `behold serve` applies, so a query that writes (`CREATE`, `MERGE`, `SET`, `DELETE` and the like) is refused. The database engine is about 23 MiB and loads after the page has drawn; the box says when it is ready.

The tables are the graph pane's: `Resource` (keyed `<member>/<id>`, with `kind`, `source`, `scopeKey`, `name`, `attrs`, `facts` and more), `CloudId`, and the `REF` and `KNOWN_AS` edges between them. For example:

```cypher
MATCH (a:Resource)-[:KNOWN_AS]->(c:CloudId)<-[:KNOWN_AS]-(b:Resource)
WHERE a.scopeKey <> b.scopeKey
RETURN a.key, b.key, c.value
```

[The graph database](/behold/using/graph-database/) lists every table and property, with more queries.

## The same loop on your estate

Serve your project or workspace, with the optional `@ladybugdb/core` peer installed beside behold so the graph pane can answer Cypher:

```sh
npm install @intentius/behold @ladybugdb/core
npx behold serve ./estate --port 4600
```

To bring a cloud account or a cluster into the same graph, index it first; `behold serve` loads every index version it finds:

```sh
npx behold index aws --account <account-id> --regions us-east-1
npx behold index kubernetes --context <kube-context>
```

Then give your agent `behold mcp` for the same directory. It finds the running serve of that directory (`--url` names one directly):

```sh
claude mcp add behold -- npx behold mcp ./estate
```

Ask the agent your question. It answers through the `ask` tool with a `cypher` argument, and `params` for the query's parameters as a JSON string. One of the recorded calls, for "What breaks if I delete the GCP load balancer's forwarding rule?", was:

```json
{
  "cypher": "MATCH (o:Resource)-[:REF*1..6]->(r:Resource {key: $key}) RETURN DISTINCT o.key AS key, o.kind AS kind, o.scopeKey AS scope",
  "params": "{\"key\": \"gcp/webRule\"}"
}
```

The answer carries the rows, the keys of the resources they name, and when each source was read. The graph pane at `/graph` on the serve runs the same query, so you can open the answer there. [Driving it from an agent](/behold/using/agents/) lists the other tools.

## Re-recording it

From a checkout of behold:

```sh
just ask-demo-record
```

It boots the estate above on emulators, asks each question through `behold mcp`, and writes `ask-demo/narration.json` and the estate it answered from to `ask-demo/estate/`. It prints one verdict line per question. A question that errors or answers nothing is left out, and the run fails when fewer than three are left. It needs Docker, kind, kubectl, the aws CLI, choudoufu v0.22.0 or newer (`CHOUDOUFU_BIN` or on `PATH`) and plunge (`PLUNGE_BIN` or on `PATH`). It runs under `e2e/lib/safe-env.sh`, which clears every real cloud credential first, and it removes the containers and the cluster it made when it ends.

The read of the real AWS account is a separate command, run by a person with the default AWS profile signed in to that account:

```sh
npm i --no-save @aws-sdk/credential-providers@3
just ask-demo-read-real-aws --account <account-id>
```

chant's lister reads the default profile through `@aws-sdk/credential-providers`, which behold does not depend on, so the first line installs it beside behold without changing `package.json`.

It reads and writes `us-west-2` only, and refuses before making anything unless every security group in that region is a default one. It makes two security groups in the region's default VPC, `behold-ask-demo-ssh` opening TCP port 22 to `0.0.0.0/0` and `behold-ask-demo-web` opening TCP port 443 to `0.0.0.0/0`, runs `behold index aws` naming the security group, ingress rule and VPC types, then deletes both groups, even when an earlier step failed, and checks that only the default groups are left. It writes the index version to `ask-demo/real-aws/index-version.json` with the account id replaced by `123456789012` everywhere, and the scope key, digest and version name computed again from the redacted content. `just ask-demo-record` loads that file as one more source. The recorder and `just ask-demo-check` both refuse a file that names any AWS account other than floci's `000000000000` and the placeholder.

Each question carries the agent's reading line, then the busy line. Each reply says that behold's query ran and how many rows it returned, then answers the question in the words it was asked, from the recorded rows, then says the Cypher is in the Cypher pane. Where a reply names a member, the member comes from a resource's key: a chant resource is keyed `<member>/<id>`, so `gcp/webRule` is in the gcp member. To change the wording in `scripts/ask-demo/questions.ts` without recording again, fill the replies from the rows already in the file:

```sh
just ask-demo-refill
```

It rewrites each question turn's `prompt`, `reading` and `reply` and the load turn's `reply` and busy line, drops a turn whose question is gone from `questions.ts` (and says so), checks the result against `ask-demo/narration.schema.json`, and fails naming a turn whose template no longer fills.

## Redeploying it

The page is a Cloudflare Worker that serves static files. One command builds the bundle into `dist-ask-demo/` and deploys it, after `npx wrangler login` once:

```sh
just ask-demo-deploy
```

`just ask-demo-check` checks the bundle before it goes out. It serves `dist-ask-demo/` with `wrangler dev`, fetches the page, `narration.json` and the WebAssembly worker, then plays a loop in headless Chrome and runs a visitor's query, printing a verdict line for each check. It fails on a missing file, a request that leaves the bundle's origin, or a content security policy violation. To check the deployed Worker:

```sh
just ask-demo-check --url https://behold-ask-demo.intentius.workers.dev
```

Every file is served with a content security policy that allows only the bundle's own origin. Its `script-src` allows `'unsafe-eval'` as well as `'wasm-unsafe-eval'`, because the database engine's WebAssembly bindings build their functions at load time; without it the engine does not start.
