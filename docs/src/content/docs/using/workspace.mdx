Since chant 0.81.0, a directory can hold many members and list them in a
`chant.workspace.json` at its root. behold serves such a workspace from that
list:

```sh
npx @intentius/behold serve ./estate      # the directory holding chant.workspace.json
```

behold reads the declaration through chant rather than parsing it itself. Every
reader goes through the same contract, which keeps behold and `chant workspace`
in agreement about the member list.

## What behold asks chant

| Question | Command |
|---|---|
| Which members are there, and can each be read? | `chant workspace ls --json` |
| What does a member hold? | `chant workspace graph --member <name>`, with `--live`, `--overlay` and `--traffic` for the live picture |

Both documents carry a contract version, and behold reads version 1. A
document written to any other version is refused with what to upgrade, because
a new contract version can change what a field means. The chant that answers
is the one the workspace root resolves: its own install, or behold's when the
root has none, which is how a Terraform-only estate with no chant of its own
stays viewable.

## What is drawn

| Member | Drawn as |
|---|---|
| `chant` and `terraform` | A box of the member's resources, read through `chant workspace graph` |
| `choudoufu` | A box of the estate's instances. The edges between them and each block's place in the source come from `chant workspace graph`; the instances, their rungs and the references to other estates come from `choudoufu live-check`, since chant's graph has one node per block and no rung or reference |
| A member chant cannot read | A box with one card that gives chant's reason code and message, such as `dir-missing` or `unknown-kind` |
| `other`, or a nested `workspace` | Nothing. It is listed when behold starts and in `behold doctor` |

Node ids are `<member>/<id>`, with the member's declared name. That is the id
chant composes too. The hand layout lives in the workspace root's
`.behold/layout.json`.

Several directories on the command line (`behold serve a b c`) are still the
loose view behold composes itself, with no declaration involved.

## Policy denials

A run whose plan the policy denies records a gate of op `policy-override` on
`chant/lifecycle`. `chant workspace status` lists it with the other gates, but
an override needs the rules that denied the plan and a person's reason, so
behold draws it as an override card with no button. The card names the subject
(a root, or SQL Yodeler's migrations Op), the denied rules and the plan digest,
read from `_gates/policy-override.jsonl`, and the command to run at your shell:

| Repo | Command on the card |
|---|---|
| terragucci (a `terragucci.yml` in the member or above it) | `npx terragucci override <root> --rule <id> --reason "..."` |
| SQL Yodeler (a `yodel.config.ts`) | `npx yodel override <env> --rule <id> --reason "..."` |
| anything else | `chant approve policy-override <subject> --rule <id> --reason "..." --plan <digest>` |

An override that counts reads as overridden until a run applies it. Once a run
records it in `_gates/policy-override/applied.jsonl` the card reads as spent,
with the time it was applied.

## Converting a `.behold.json` member list

The `members` key in `.behold.json` is deprecated. When a
`chant.workspace.json` sits beside it, behold ignores the key and prints a
warning at startup. An estate root that has only the `.behold.json` list
converts with one command:

```sh
npx @intentius/behold doctor ./estate --fix
```

This writes `chant.workspace.json` in the root and never over an existing one.
It then runs `chant workspace check` on what it wrote.

- Each member keeps the name behold already composed it under, so a chant
  member's node ids don't change.
- A Terraform member holding several roots becomes one member per root, because
  a chant `terraform` member is a single root.
- Any `terraform` or `choudoufu` member makes the declaration pin
  `@intentius/chant-lexicon-terraform`, which supplies both kinds.
- The saved layout in the first member's `.behold/layout.json` is copied into
  the root, and its node ids are rewritten to the declared names.

<Aside type="note" title="What --fix writes">
Two files: `chant.workspace.json` and `.behold/layout.json`, both in the estate
root. The old layout file and `.behold.json` stay as they were. Every other
doctor run writes nothing.
</Aside>
