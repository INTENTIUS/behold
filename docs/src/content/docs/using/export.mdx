---
title: Export a snapshot
description: Freeze the estate into a self-contained static site anyone can open.
---

`behold export` captures whatever you are looking at into a **static folder** that any host can serve. Read-only, and fully interactive.

```sh
npx behold export --out ./behold-export
npx serve ./behold-export
```

Pan and zoom, the zoom dial, the inspect pane and the env/tier pickers all work client-side. There is no backend and no live observe: it is a snapshot, and it says so.

## What it captures

Every read endpoint for the whole lens matrix (each env/tier × zoom × radial), rendered in-process by **the same handlers the live server runs**. A snapshot is byte-identical to what live would have shown at that moment.

## The graph as one file

Every export also writes `graph.json` at the bundle root: the opening view at detail 2 as a [`behold-graph/1` document](/behold/using/graph-document/), so a dashboard, a portal or a script can read one URL instead of the snapshots, whose names change with their bytes. It follows `--open-env` (the opening environment's overlay) and `--no-source`, which leaves each card's source text out of it as it does the snapshots (what it removes is listed under [What it leaves out](#what-it-leaves-out)). In an estate of several projects every card is in it, not the stacked ones. `manifest.json` names it as `graph` and lists it in `files`, and `--publish` uploads it with the rest of each commit's folder, so it sits at `<prefix>/views/<name>/<commit>/graph.json`.

```sh
npx behold export . --out ./behold-export
jq '.nodes | length' ./behold-export/graph.json
```

Once the single-file viewer is built (behold#1070), the export also writes `behold.html`, the same view as one HTML file that opens from disk. `--single-file <path>` writes only that file, reading just the opening view, for a CI artifact. Until then, `--single-file` stops and says so.

## Cypher in the bundle

`--graphdb` makes the bundle's `/graph` page answer Cypher, resolve and templates with no server. The export writes the graph pane's rows to `graphdb.json` (attribute values masked, as `serve` masks them), with the table layout and the template catalog, chant's and the project's `.chant/templates.json`. Beside it go LadybugDB's WebAssembly build (`lbug-wasm.js` and its worker, `lbug_wasm_worker.js`) and `graph-db-wasm.js`, which builds the database in the page. The page draws first and fetches the engine afterwards; the Cypher box says it is loading until the database is ready.

```sh
npx behold export . --out ./behold-export --graphdb
```

A query in the page goes through the same read-only check as on `serve`, and is refused in the same words; answers stop at 2,000 rows and a query at 8,000 characters. The worker is about 23.4 MiB at 0.22.3. Cloudflare serves static files up to 25 MiB, so the export stops, naming the file's size and the engine's version, when the worker or `graphdb.json` is larger. The default build needs no cross-origin isolation headers. An export without `--graphdb` carries none of these files.

## With a live overlay

```sh
npx behold export ../my-project --env prod --out ./behold-export
```

Freezes the drift colours as they were when you exported. Useful for an incident write-up, or for showing someone an estate they have no credentials for.

Each captured environment also carries its [health and rotation](/behold/using/reading-the-graph/#health-and-rotation), read once with `chant lifecycle health` when the export runs: the health marks on the cards and the Route 53 records out of rotation are drawn as they were then. The read uses the export's own credentials and endpoints (`AWS_ENDPOINT_URL` and the like, or the environment's declared endpoint), the same as the drift overlay. A chant older than 0.124.33 captures the refusal, and the bundle draws no health marks.

## The view it opens on

A bundle opens on the source graph (`env: (source)`) at the zoom behold would pick for the estate. `--open-env` and `--open-zoom` choose something else:

```sh
npx behold export ../my-workspace --open-env frozen --open-zoom composites --out ./behold-export
```

`--open-env` takes one of the environments the export captures, which are the ones the estate declares. `--open-zoom` takes `components`, `logical`, `composites`, `resources` or `attributes`, and `ops` when the estate has emitted Ops. The export refuses any other value before it captures anything, and says which values it would take. The choice is written to the bundle's `manifest.json` as `opening`. A link with its own `?env=` or `?zoom=` still opens where the link points.

## A line at the foot of the page

`--note` puts one line of text under the graph, such as how to run the estate yourself. A span in backticks is drawn as code, and nothing else is markup:

```sh
npx behold export . --note 'Run this yourself: `npx @intentius/behold demo three-cloud`' --out ./behold-export
```

The note is at most 200 characters on one line, and the export refuses anything else before it captures. It is written to `manifest.json` as `note`. [The three-cloud demo](/behold/using/three-cloud/) ends its page this way.

## A declared workspace

Exporting a directory that holds a `chant.workspace.json` names the bundle after the workspace, not after its first member. The generated `wrangler.jsonc` names the Worker `behold-<workspace name>` (`behold-three-cloud` for a workspace declared as `three-cloud`), and `manifest.json` carries `workspace` with the declared name and `projectDir` with the workspace root's directory name. `--name` still overrides the Worker name. A single project is named after its directory, as before.

## What it leaves out

A bundle carries the picture and nothing about the machine that made it: no list of your recent projects, no user name, and every absolute path reduced to its directory's name.

A Terraform card carries its root's whole source file, and its attribute values as written. `--no-source` leaves the source text out of every snapshot and out of `graph.json` and `behold.html`:

```sh
npx behold export . --no-source --out ./behold-export
```

It removes:

- `attrs.source`, a root's whole file.
- Any attribute value, at any depth of a card's `attrs` (the body, the evaluated arguments, a stack's instances), that holds a line break: a heredoc body, a multi-line string, a multi-line expression with its comments.
- Any value that holds a heredoc opener (`<<`), an interpolation that computes something (`${length(var.x)}`, `${jsonencode(...)}`), or a single-line string longer than 120 characters.
- The text of an expression: a `for_each` or `count` string, an `expression` in an instance rollup, and each entry under `evaluated.stopped`, unless it is a plain reference such as `local.groups`.

Each of them is replaced by the text `value left out (--no-source)`, which the card shows where the value was. It keeps every name, type, address, file name and line, edge, group and status, every reference (`aws_vpc.main.id`, `${var.region}`), every number and boolean, and each short single-line literal (`us-east-1`, a tag value). The same rule applies to every lexicon, so a long annotation or a multi-line ConfigMap value on a Kubernetes card is left out too. It does not read the values for secrets: a short literal that is a secret stays, so keep secrets out of the files, with or without the flag. The flag changes the bundle only. `behold graph` already leaves out `attrs.source` unless you pass `--source`, and does not change attribute values.

## A terragucci estate

`--terragucci <src>` captures the marks [`serve --terragucci`](/behold/using/terragucci/) shows, with the same dates, and the audit record's timeline as one more snapshot (a refusal or an absent record is captured as the lane shows it, and does not fail the export). `--publish s3://<bucket>/<prefix>/views/<name>` also uploads the bundle there, signed with AWS credentials from the environment; it writes only under a `views/<name>` directory, one folder per commit (`views/<name>/<commit>/`, the checkout's `HEAD` or `--commit <sha>`), with `history.json`, `latest.json` and an `index.html` that opens the newest beside them; `--keep <n>` (default 30) is how many commits stay. [Publish a view](/behold/using/terragucci/#publish-a-view-beside-the-estate-page) says how terragucci's estate job puts it beside `estate.html`.

## Hosting it

The bundle is deploy-ready for Cloudflare, since `export` writes an assets-only `wrangler.jsonc`:

```sh
cd ./behold-export && npx wrangler deploy
```

GitHub Pages, S3 and nginx work too. [Publish to GitHub Pages](/behold/using/pages/) has a workflow that deploys the export on each push to `main` and refuses on a private repository. The live app needs Docker and a chant subprocess and cannot run on an edge worker; the pre-baked export can.
